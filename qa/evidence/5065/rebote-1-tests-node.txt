3) CAUSA RAIZ
-------------
No es el test: es phases-alias.js. `loadOfficialPhases()` parseaba el bloque
`pipelines:` de config.yaml con un regex de bloque unico:

    /^pipelines:\s*\n((?:[ \t]+.*\n)+)/m

`(?:[ \t]+.*\n)+` exige que TODA linea del bloque arranque con espacio/tab, y
config.yaml tiene una LINEA EN BLANCO separando `definicion:` de `desarrollo:`
(linea 12). El resultado depende del fin de linea del checkout:

$ node -e "... match sobre cada variante ..."
  config LF   (worktree, 99026 bytes) -> match PARCIAL: captura 8 lineas
                                          = solo el pipeline `definicion`
  config CRLF (repo ppal, 100817 bytes) -> NO MATCH
                                          = cae a HARDCODED_FALLBACK (10 fases)

$ node -e "const pa=require('./.pipeline/lib/commander/phases-alias'); \
           console.log(pa.loadOfficialPhases().map(o=>o.full))"
  worktree (LF):   ["definicion/analisis","definicion/criterios","definicion/sizing"]
  repo ppal (CRLF):["definicion/analisis",...,"desarrollo/validacion",...,"desarrollo/entrega"]

$ file .pipeline/config.yaml
  repo ppal: UTF-8 text, with CRLF line terminators
  worktree : UTF-8 text                      (LF)

Por que difieren si el blob de git es el mismo: .gitattributes (#4695) fuerza
`*.yaml text eol=lf`. La copia del repo principal quedo con CRLF de antes de esa
regla; todo checkout/worktree nuevo sale LF.

$ git check-attr text eol -- .pipeline/config.yaml
  .pipeline/config.yaml: text: set
  .pipeline/config.yaml: eol: lf

=> El bug estaba TAPADO en el repo principal (el fallback hardcodeado tenia
   por casualidad las 10 fases correctas) y ACTIVO en todos los worktrees.

Impacto real (no solo del test): el unico consumidor es
.pipeline/lib/commander/rechazar-handler.js, o sea el comando /rechazar de
Telegram. En cualquier checkout LF, `/rechazar <issue> dev|build|verificacion|
validar|linteo|aprobacion|entrega` respondia "Alias X apunta a fase Y que el
config actual no incluye". Se rompian las 7 fases de `desarrollo`.

Nota sobre por que aparecio recien ahora: el commit previo de este issue
(1daef93ec) agrego pipeline.config.json a PIPELINE_ONLY_PATTERNS, con lo cual el
tester dejo de rutear a gradle y paso a correr la suite Node. El fallo es
preexistente; ese cambio solo lo destapo.
