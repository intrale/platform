Configuracion Google Drive para Videos QA (OAuth)

Issue #1805 — Usa tu cuenta personal de Google (no requiere Google Workspace)

NOTA: Service Accounts no tienen cuota de almacenamiento en Drive personal. Esta guia usa OAuth 2.0 con tu cuenta, que SI tiene los 15GB gratuitos.

Paso a paso

1Crear proyecto en Google Cloud Console

Ir a console.cloud.google.com/projectcreate

Nombre: intrale-qa y click "Crear"

2Habilitar Google Drive API

Ir a APIs > Google Drive API y click "Habilitar"

3Configurar pantalla de consentimiento OAuth
  1. Ir a OAuth consent screen
  2. Tipo: Externo (para cuentas personales)
  3. Nombre de app: Intrale QA
  4. Email de soporte: tu email
  5. Scopes: agregar https://www.googleapis.com/auth/drive.file
  6. Test users: agregar tu email
  7. Guardar
4Crear credenciales OAuth
  1. Ir a Credenciales
  2. Click "Crear credenciales" > "ID de cliente OAuth"
  3. Tipo: App de escritorio (Desktop app)
  4. Nombre: intrale-qa-cli
  5. Click "Crear"
  6. Copiar Client ID y Client Secret
5Ejecutar script de autorizacion

En la terminal de Claude Code, ejecuta:

! node scripts/google-drive-oauth-setup.js <CLIENT_ID>

El client secret NO se pasa por linea de comandos (#5217): los argumentos son visibles en la tabla de procesos del SO y quedan en el historial del shell (CWE-214). El script lo pide por prompt, sin eco, o lo toma de GOOGLE_OAUTH_CLIENT_SECRET. Pasarlo como segundo argumento ahora falla con error.

El script va a:

  1. Pedirte el Client Secret por prompt (no se muestra en pantalla)
  2. Pedirte el Drive folder ID de QA (ENTER para conservar el ya guardado)
  3. Mostrarte una URL — abrila en el browser
  4. Autorizas con tu cuenta Google
  5. El script guarda las credenciales en el store canonico ~/.claude/secrets/credentials.json, bajo el namespace google_drive, y te confirma que claves escribio (por nombre, nunca por valor)
6Crear carpeta en Google Drive
  1. Ir a drive.google.com
  2. Crear carpeta: Intrale QA
  3. Copiar el ID de la URL: https://drive.google.com/drive/folders/1AbCdEfG...
  4. Pegarlo cuando el script del paso 5 te lo pida (o exportar GOOGLE_DRIVE_FOLDER_ID antes de correrlo)

NO lo agregues a .claude/hooks/telegram-config.json. Ese archivo esta trackeado en git: un git reset --hard — que ocurre en cada respawn del entorno — lo restaura sin tus valores, y la evidencia de QA deja de subirse en silencio. Es exactamente el defecto que cerro #5217. Si el folder ID no resuelve, la evidencia se sube a la raiz del Drive y el script te avisa por consola.

7Verificar 
node qa/scripts/qa-video-share.js \
  --issue 9999 --title "Test upload" \
  --sprint "SPR-TEST" \
  --videos "qa/evidence/1781/qa-video-final.mp4" \
  --verdict "APROBADO" --passed 1 --total 1

Resultado en el store canonico

Todo queda en ~/.claude/secrets/credentials.json — fuera del repo, inmune a reset --hard, clean y checkouts. Estructura (claves anidadas bajo google_drive, no los nombres flat del formato legacy):

{
  "google_drive": {
    "oauth_client_id":     "<client id>",
    "oauth_client_secret": "<client secret>",
    "oauth_refresh_token": "<refresh token>",
    "drive_folder_id":     "<folder id>"
  }
}

Precedencia de resolucion: env → store canonico → .claude/hooks/telegram-config.json (legacy, solo lectura, nunca destino de escritura). Un valor vacio o placeholder en un nivel no corta la cadena: cae al siguiente. Ver docs/runbooks/credential-rotation.md.
